## Why

当前统一 AI 助手只是一次请求内的单工具路由：没有服务端会话、连续观察与决策循环、暂停恢复、执行预算和工具级授权，因此无法可靠承载“检查一支家谱、持续补查、向用户澄清并形成修订草稿”这类真正的代理任务。现有修订、审校、发布和审计基础已经具备，现在适合引入一个受约束、可追踪且始终受人工控制的 Agent Runtime。

## What Changes

- 新增受约束的 Agent Runtime，允许模型在明确的轮次、耗时和工具预算内执行“观察—选择工具—读取结果—继续或停止”的多步循环。
- 持久化 Agent 会话、消息、运行、步骤和工具调用，使任务可以暂停、澄清、恢复、取消和审计。
- 建立统一工具注册协议，为每个工具声明输入输出模式、权限、只读或提案级副作用、超时和可审计元数据。
- 新增人工介入状态：Agent 遇到歧义、敏感操作或预算边界时必须请求用户澄清或确认，而不是自行猜测。
- 将正式数据写入继续隔离在不可变修订组及既有审校发布流程之后；Agent 不得直接创建、修改或发布正式家谱记录。
- 提供首个“家谱资料补全 Agent”：分析指定人物或分支的资料缺口，执行必要查询，提出聚焦问题，并生成可审校的修订草稿或结论报告。
- 统一现有录入、关系查询、人物查询和资料缺口分析能力到新工具协议，同时保持现有业务规则和确定性亲属推理。
- 引入 LangChain JS 作为模型、消息、工具与结构化输出的统一抽象，并使用 LangGraph 构建可持久化、可中断恢复的 Agent 状态图，为后续 OCR、多模态资料提取和更多领域工具提供一致的扩展边界。

## Capabilities

### New Capabilities

- `bounded-agent-runtime`: 定义持久化会话、多步运行循环、预算限制、工具协议、暂停恢复、取消、权限与可观测性要求。
- `genealogy-completion-agent`: 定义资料补全 Agent 如何分析家谱缺口、进行多步调查、请求澄清并产出受审校流程保护的结果。

### Modified Capabilities

- 无。

## Impact

- 数据模型将新增 Agent 会话、消息、运行、步骤与工具调用相关实体及迁移。
- `src/lib/agent/` 将从单次工具路由演进为领域无关运行时、工具注册表和具体家谱 Agent 的分层结构。
- `/api/agent/chat` 的服务端执行方式和流式事件协议将扩展，并新增会话恢复、运行继续和取消入口；现有客户端需要适配持久化会话与人工介入状态。
- 现有录入草稿、关系查询、人物查询、权限服务、修订组、审计和发布机制将被复用，不改变正式数据必须经过审校发布的原则。
- 新增 LangChain JS、LangGraph 及对应模型适配依赖；现有 OpenAI/DeepSeek 配置将迁移到统一模型适配层，并保持提供方可替换。
