## ADDED Requirements

### Requirement: 系统必须持久化家谱范围内的 Agent 会话与运行
系统 SHALL 将 Agent 会话、消息、运行、步骤和工具调用持久化，并 MUST 将每个会话绑定到一个家谱及其创建者。所有读取、恢复和取消操作 MUST 重新校验当前用户对该家谱的权限。

#### Scenario: 用户恢复自己的 Agent 会话
- **WHEN** 获得授权的用户打开一个先前暂停的 Agent 会话
- **THEN** 系统 SHALL 从已持久化消息和检查点恢复会话状态
- **AND** 系统 SHALL NOT 暴露其他家谱或其他无权访问会话的数据

#### Scenario: 用户失去家谱访问权限
- **WHEN** 会话创建者在运行恢复前失去目标家谱的访问权限
- **THEN** 系统 MUST 拒绝恢复或执行运行
- **AND** 系统 SHALL NOT 执行任何工具调用

### Requirement: Agent 运行必须执行有界多步循环
系统 SHALL 允许 Agent 在一次运行中连续选择和执行多个已注册工具，但 MUST 对模型轮次、工具调用数、总耗时、重试次数和上下文用量执行固化的运行预算。每个模型或工具步骤完成后，系统 MUST 在继续前检查剩余预算。

#### Scenario: Agent 连续使用多个只读工具
- **WHEN** 完成目标需要先查找人物、再读取关系并分析资料缺口
- **THEN** Agent SHALL 在同一运行内按步骤调用所需的已授权只读工具
- **AND** 系统 SHALL 持久化每一步的状态和安全摘要

#### Scenario: 运行耗尽预算
- **WHEN** 任一硬性预算在目标完成前耗尽
- **THEN** 系统 MUST 停止新的模型与工具调用
- **AND** 运行 MUST 以 `BUDGET_EXHAUSTED` 结束并返回已完成工作摘要

### Requirement: Agent 工具必须通过统一注册表执行
每个 Agent 工具 MUST 声明稳定名称、版本、输入输出模式、权限动作、超时和副作用等级。系统 MUST 在执行前验证参数、当前权限和副作用策略，并 MUST 在执行后验证结构化结果。

#### Scenario: 模型提交无效工具参数
- **WHEN** 模型生成的工具参数不符合注册模式
- **THEN** 系统 MUST 拒绝执行工具
- **AND** 系统 SHALL 记录可分类的校验失败而不调用底层业务服务

#### Scenario: 模型请求未注册的敏感工具
- **WHEN** 模型请求发布、批准、撤回、删除或其他未向 Agent 注册的能力
- **THEN** 系统 MUST 拒绝该请求
- **AND** 运行 SHALL 进入失败或人工介入状态，而不得执行正式数据操作

### Requirement: Agent 不得绕过正式修订工作流
Agent 自主执行的工具 MUST 限于只读调查。任何可能形成业务变更的操作 MUST 仅创建工作草稿或不可变修订组，并 MUST 经过明确用户确认及既有审校发布流程；Agent MUST NOT 直接创建、修改、批准或发布正式家谱记录。

#### Scenario: Agent 发现可补充的人物事实
- **WHEN** Agent 根据用户提供的信息形成可结构化的人物或关系变更
- **THEN** 系统 SHALL 先生成可审阅草稿并请求用户确认
- **AND** 确认后系统 SHALL 只创建不可变修订组，不得直接写入正式记录

#### Scenario: 用户要求 Agent 自动发布
- **WHEN** 用户要求 Agent 跳过审校并直接发布变更
- **THEN** Agent MUST 拒绝绕过正式工作流
- **AND** 系统 SHALL NOT 向运行图提供发布工具

### Requirement: Agent 运行必须支持结构化人工介入
当目标存在身份歧义、关系方向不明、证据不足或即将执行提案级工具时，系统 MUST 暂停运行并持久化结构化介入请求。恢复命令 MUST 与等待中的运行、动作参数哈希、家谱修订号和有效期匹配。

#### Scenario: 多个人物与目标姓名匹配
- **WHEN** Agent 无法唯一确定用户所指人物
- **THEN** 运行 MUST 进入 `WAITING_FOR_USER`
- **AND** 系统 SHALL 提供可区分的候选项且不得自行选择

#### Scenario: 确认后家谱数据已变化
- **WHEN** 用户确认的待执行动作所绑定家谱修订号不再是当前版本
- **THEN** 系统 MUST 使原确认失效
- **AND** Agent SHALL 重新调查并在需要时请求新的确认

### Requirement: Agent 运行必须可取消、失败和安全恢复
系统 SHALL 支持取消活动运行，并 SHALL 将工具错误、模型错误、模式错误和预算终止保存为可区分状态。恢复 MUST 从最后一个兼容且完整的检查点继续，并 MUST 通过幂等键防止重复执行工具副作用。

#### Scenario: 用户取消等待中的运行
- **WHEN** 获得授权的用户取消处于运行或等待状态的 Agent 运行
- **THEN** 系统 MUST 将其标记为 `CANCELLED`
- **AND** 系统 MUST 拒绝该运行后续的恢复或工具执行

#### Scenario: 请求在工具完成后中断
- **WHEN** 工具已经产生持久结果但响应在记录下一检查点前中断
- **THEN** 恢复逻辑 MUST 使用幂等键识别已有结果
- **AND** 系统 MUST NOT 重复执行同一提案级操作

### Requirement: Agent 轨迹必须可观测且保护敏感数据
系统 SHALL 为每次运行记录模型提供方、模型、提示词版本、图版本、工具版本、步骤耗时、Token 用量、终止原因和错误分类。审计与日志 MUST 只保存安全摘要，不得默认保存文件正文、密钥、对象存储地址或不必要的敏感个人信息。

#### Scenario: 管理员排查失败运行
- **WHEN** 获得授权的管理员查看失败运行
- **THEN** 系统 SHALL 提供足以定位失败节点、工具和错误类别的轨迹
- **AND** 轨迹 SHALL 隐去密钥及未授权的原始资料内容

### Requirement: 同一会话必须串行化活动运行
一个 Agent 会话在任意时刻 MUST 最多存在一个活动运行。系统 MUST 区分对等待运行的恢复命令与创建新目标的请求，避免并发步骤修改同一检查点。

#### Scenario: 客户端重复提交运行请求
- **WHEN** 同一会话已有活动运行且客户端再次提交启动请求
- **THEN** 系统 MUST 返回现有活动运行或冲突响应
- **AND** 系统 MUST NOT 创建第二个并发活动运行
