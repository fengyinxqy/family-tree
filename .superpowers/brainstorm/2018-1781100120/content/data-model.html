数据模型设计

核心实体关系 — 支撑多家族、基础家谱信息

实体关系图

核心表：5 张 | 多租户入口为 Family
👤 User（用户表）
id · email · name · password_hash · created_at
↕ FamilyMember（多对多 + 角色）
🏠 Family（家族表）
id · name · description · created_by → User · created_at
↓ 1:N（一个家族有多个人物）
🧑 Person（人物表）⭐ 核心
id · family_id → Family · name · gender · birth_date · death_date · bio · created_at · updated_at
↕
💍 Relationship（关系表）
id · family_id → Family · type（配偶/子女）· person_a → Person · person_b → Person · sort_order · created_at
↕
👥 FamilyMember（家族成员角色表）
id · user_id → User · family_id → Family · role（admin/editor/viewer）· joined_at

关系类型说明

配偶关系 (spouse)

双向关系。person_a 和 person_b 互为配偶。通过 type='spouse' 标识。

子女关系 (child)

单向关系。person_a 是父/母，person_b 是子女。通过配偶关系可推断双亲。

排序字段

子女之间通过 sort_order 控制显示顺序（长幼有序），配偶之间按结婚时间排序。

多租户数据隔离策略

每张业务表（Person、Relationship）都带 family_id 外键。 API 层通过中间件从当前登录用户和访问的家族上下文中提取 family_id， 所有数据库查询自动带 WHERE family_id = ? 条件，确保跨家族数据绝不泄漏。
