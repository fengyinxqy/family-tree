# 协作、发布与管控操作指南

## 修订组

### 基本概念
- **修订组（Revision Group）** 是 AI 多轮录入和关系建议的输出容器，包含一个或多个有序修订成员。
- **导入修订组** 是 JSON 备份或交换包确认后生成的零成员不可变批次；导入数据保存在服务端来源快照中，必须审校发布后才替换正式数据。
- **独立修订（Standalone Revision）** 是仅含一个已有端点关系的修订（如纯关系建议），不需要组容器。
- 修订组成员在发布前使用临时引用（`tmp:person-0`）相互引用，避免正式标识符提前暴露。

### 限制
- 最大成员数：200 个
- 临时引用模式：`tmp:[a-zA-Z0-9_-]{1,120}`
- 发布事务使用 Serializable 隔离级别

## 工作流

DRAFT → IN_REVIEW → APPROVED → PUBLISHED
                → CHANGES_REQUESTED（退回）

- DRAFT：创建后可修改 payload
- IN_REVIEW：提交审校，不可修改
- CHANGES_REQUESTED：退回，需要派生新草稿
- APPROVED：通过审校，可发布
- PUBLISHED：已发布到正式数据

### 导入工作流

1. 导入预览只校验文件、生成差异摘要和五分钟有效的一次性确认。
2. 确认后创建 DRAFT 导入修订组，不修改人物、关系、事件、资料或文件正式记录。
3. 作者提交审校；审校者通过后，由 OWNER/ADMIN 发布。
4. 发布在 Serializable 事务中重新校验家族版本，创建 `pre_import` 快照，替换正式数据、递增 `dataRevision` 并写审计。
5. 任一数据库写入或审计写入失败时整体回滚；交换包文件在发布前保持私有且没有可下载的业务记录。

### 各阶段权限要求
- 创建修订/组：EDITOR 及以上
- 提交审校：EDITOR 及以上
- 审校决定：REVIEWER 及以上（不可自审，OWNER/ADMIN 可自审需填写覆盖原因）
- 发布：ADMIN 及以上
- 查看审计历史：仅 OWNER

## 成员与所有权

| 角色 | 主要能力 |
|------|----------|
| OWNER | 全部能力；唯一可执行所有权转移、快照恢复和删除恢复 |
| ADMIN | 管理非 OWNER 成员、创建/提交修订、审校和发布 |
| EDITOR | 查看工作区、创建和提交修订 |
| REVIEWER | 查看工作区并审校他人修订 |
| VIEWER | 仅查看已发布内容 |

- 邀请绑定规范化邮箱、有效期和非 OWNER 角色；明文令牌只返回一次，数据库仅保存哈希。
- 邀请接受时重新核验登录邮箱、令牌状态和家族成员状态；接受、建成员和审计在同一事务中完成。
- 停用或移除成员后，其下一次服务端请求立即失去访问权。
- 所有权只能由当前 OWNER 转给同家族活跃成员；新 OWNER、原 OWNER 降为 ADMIN、`FamilyTree.ownerId` 与审计必须原子提交。

## 来源追溯

提交审校前必须声明至少一个来源条目，支持四种来源类型：

| 类型 | 说明 | 验证规则 |
|------|------|----------|
| MATERIAL | 引用已有文献资料 | 资料必须属于当前家族且未被删除
| MEDIA_OBJECT | 引用已有媒体文件 | 媒体必须属于当前家族
| INTAKE_SNAPSHOT | AI 录入原文快照 | 自动生成，包含 SHA-256 哈希和前 500 字符摘要
| MANUAL_KNOWLEDGE | 人工知识声明 | 不需要外部引用，但必须填写理由

## 发布后更正

- 产品不提供直接撤回已发布内容的入口或 API。
- 需要更正或移除已发布内容时，从当前正式状态派生新 DRAFT，重新提交审校并发布。
- 历史版本与审计记录保持不可变；旧版本部署期间已经撤回的数据继续保持不可见，不会因功能下线而重新出现。

## 迁移与回滚

### 迁移策略
1. 先部署成员、邀请、内容修订、修订组与来源表，并为每个既有家族回填唯一活跃 OWNER。
2. 添加 `withdrawnAt` 可见性字段、必要索引及审计表 UPDATE/DELETE 拒绝触发器。
3. 已有正式记录保持可见（`withdrawnAt IS NULL`），不伪造历史审校或来源。
4. 执行 `prisma migrate deploy` 后运行角色矩阵、正式读取和导入审校检查。

### 回滚策略
1. 禁用邀请、AI 录入应用、导入提交、来源提交和发布端点。
2. 已有正式记录和已发布修订保持有效
3. 新修订组和来源记录转为只读历史
4. 可见性默认保持最近一次成功发布的状态
5. 回退数据库结构前导出成员、修订与审计数据；不可删除已经发生的审计记录。

## 审计历史

审计操作在业务事务中自动创建，支持以下协作操作类型：

- 人物/关系创建、修改、删除、恢复
- 修订创建、提交、审校、发布
- 修订组创建、提交、审校、发布
- 成员邀请、接受、撤销
- 角色变更、停用、重新激活
- 所有权移交
- 快照创建与恢复

安全摘要规则：
- 只包含稳定 ID、内容类型、计数、角色、状态和安全来源标签
- 邀请令牌、完整修订 payload、录入原文、凭证和文件字节不写入审计摘要
- 历史撤回审计若已存在则继续只读保留
- 审计 JSON 在持久化前递归脱敏 token、password、credential、storage key、文件字节和业务 payload 字段。
- 数据库触发器拒绝 `operation_batches` 与 `audit_entries` 的 UPDATE/DELETE；更正只能追加新操作。
