# 家谱网站 V1.1 路线图

## 目标

V1.1 的目标不是继续堆新功能，而是把当前 MVP 从“能演示”推进到“能稳定使用、能持续迭代”的阶段。

这一阶段聚焦 3 个核心方向：

- 补齐基础使用闭环：让用户能持续维护自己的家谱，而不是一次性录入
- 强化 AI 可用性：让 Agent 真正成为录入和问答助手，而不是单点能力展示
- 提升工程稳定性：为后续多人协作、资料沉淀和更复杂关系推理打基础

## 版本原则

- 所有新增能力都优先服务现有主链路：录入人物、维护关系、浏览树图、问答推理
- AI 输出默认进入“可确认、可回退、可追溯”的流程
- 每个迭代项都尽量原子化，避免大而散的混合提交
- 优先补齐中文家谱语义，而不是先做泛化功能平台

## 里程碑拆分

### P0：高优先级，下一阶段直接做

#### 1. 成员搜索与树图定位

目标：解决“树大以后找不到人”的问题。

范围：

- 增加按姓名搜索成员
- 点击搜索结果后，自动定位到对应节点
- 高亮当前命中的人物节点
- 支持清空搜索状态，恢复普通浏览

交付标准：

- 50 人以上家谱中，能在 3 秒内找到目标成员
- 搜索结果与树图定位联动稳定

#### 2. AI 录入草稿的多轮澄清

目标：把当前“一次性解析”升级成“能追问”的录入流程。

范围：

- 当人物匹配不唯一时，Agent 能提出明确澄清问题
- 当关系缺少关键信息时，Agent 能继续追问
- 支持用户补充一句话后继续在原草稿上更新
- 草稿区保留“待确认项”和“继续提问建议”

交付标准：

- 至少支持 3 类澄清：重名、缺失关系方向、代际不明
- 用户不需要从头重新输入整段口述

#### 3. 关系引擎扩展中文亲属称谓

目标：减少“存在路径但不会命名”的情况。

范围：

- 继续补全伯、叔、姑、姨、舅、侄、甥、堂、表等常见旁系称谓
- 支持更明确的正向称谓和逆向称谓
- 输出解释时同步说明推理路径
- 对无法精确命名的关系给出更友好的过渡描述

交付标准：

- 常见三代内旁系关系覆盖率显著提升
- 问答结果不再频繁落入笼统兜底文案

### P1：中优先级，P0 完成后推进

#### 4. 人物详情增强

目标：让人物页从“基础信息卡”升级成“可长期维护的档案卡”。

范围：

- 增加别名、排行、籍贯、备注等字段
- 允许补充人物事件，如出生、婚姻、迁徙、离世
- 支持更清晰的关系摘要展示

#### 5. 关系维护能力增强

目标：提升家谱编辑质量，减少脏数据。

范围：

- 修改已有关系
- 删除或断开关系
- 合并重复人物
- 处理父母顺序、重复子女边、孤立人物

#### 6. 导入导出能力

目标：给用户最基本的数据安全感。

范围：

- 导出 JSON 备份
- 导入 JSON 还原
- 后续预留 Excel / GEDCOM 接口

### P2：后续版本储备

#### 7. 多家谱空间

- 一个账号支持多个家谱
- 家谱列表页与切换入口

#### 8. 协作与权限

- 邀请家人共同维护
- 只读 / 可编辑 / 审核权限

#### 9. 资料中心

- 照片、证件、老谱扫描件上传
- 人物与资料绑定

#### 10. 时间线视图

- 按人物和家族查看事件时间线
- 让树图之外还有另一种浏览方式

## 推荐执行顺序

建议按下面顺序推进，避免功能之间互相卡住：

1. 成员搜索与树图定位
2. 关系引擎扩展中文亲属称谓
3. AI 录入草稿多轮澄清
4. 人物详情增强
5. 关系维护能力增强
6. 导入导出能力

原因：

- 搜索定位最直接提升可用性
- 关系命名增强对问答体验立竿见影
- 多轮澄清会牵涉 Agent 状态流，适合在前两项稳定后再扩展

## 工程配套任务

这些不一定作为独立产品功能，但建议穿插进行。

### 测试

- 为关系引擎补单元测试
- 为 Agent 草稿流程补接口测试
- 为树图搜索定位补基础交互测试

### 文案与编码清理

- 清理现有乱码中文
- 统一家谱、成员、人物、关系等术语
- 减少中英文混杂显示

### 性能

- 大树渲染性能观察
- 树布局计算优化
- Agent 接口响应时间记录

### 可观测性

- 记录 AI 请求失败原因
- 记录关系推理未命中场景
- 为后续迭代积累真实问题样本

## 下一步建议

如果按 V1.1 正式开做，建议第一批 issue 直接建成下面 3 个：

### Issue 1：成员搜索与树图定位

- 增加搜索输入框
- 搜索结果列表
- 节点定位与高亮
- 清空与重置状态

### Issue 2：关系引擎补全旁系中文称谓

- 梳理路径模式
- 增加命名规则
- 增加逆向称谓
- 补充测试样例

### Issue 3：AI 录入草稿多轮澄清

- 草稿状态续写
- 澄清问题格式
- 前端继续回答入口
- 草稿更新机制

## 备注

这份路线图默认当前 MVP 已具备这些基础：

- 用户登录与家谱隔离
- 人物与关系录入
- 树图展示
- AI 草稿录入
- AI 关系问答

如果后续要进入 V1.2，重点可以转向：

- 多家谱
- 协作权限
- 家族资料沉淀
