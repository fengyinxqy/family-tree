# 家谱云 V1.2–V1.4 产品路线图

## 路线图定位

MVP 已经完成“能录、能看、能问”的基础闭环。后续版本不再以横向堆叠页面为目标，而是逐步把产品推进为一套可信、可传承、可共同维护的数字家谱。

产品北极星：

> 帮助一个家庭把散落在老人讲述、纸质族谱、照片和个人记忆中的资料，整理成一套可信、可传承、可共同维护的数字家谱。

整体演进路径：

```text
MVP：能录、能看、能问
          │
          ▼
V1.2：可信、可恢复、可追溯
          │
          ▼
V1.3：扫描件、照片、文献进入系统
          │
          ▼
V1.4：多人协作、审校与发布
```

## 当前基线

MVP 及 V1.1 阶段已经具备：

- 用户注册、登录与家谱数据隔离
- 多家谱空间创建、切换和删除
- 人物档案、人物事件和关系维护
- 家谱树、世系、分支和时间线浏览
- 成员搜索、树图定位和节点高亮
- AI 多轮澄清录入与人工确认落库
- AI 亲属关系问答和中文称谓推理
- 当前家谱的 JSON 导入与导出

目前主要缺口：

- 删除恢复、操作历史和版本快照
- 完整的数据一致性校验
- GEDCOM 等标准格式交换
- 文献、照片和扫描件的真实资料模型
- OCR 提取结果的来源追溯与审校
- 家谱成员、角色权限和协作审核
- 工程规范清账、交互测试和可观测性

## 版本原则

- 优先建立可信数据闭环，再扩展展示型页面。
- 所有 AI 生成内容必须经过确认，并保留来源。
- 家谱协作以异步贡献和审校为主，不优先投入实时协同。
- 数据导入默认先预检，不直接覆盖现有内容。
- 每个版本都应有独立、可验收的用户价值。

## V1.2：可信家谱档案

建议周期：2～3 周。

目标：让用户敢于长期维护真实家谱，即使发生误操作或数据冲突，也能发现、解释和恢复。

### P0：数据安全与纠错闭环

- 为人物和关系增加软删除能力
- 支持最近操作撤销或从历史版本恢复
- 记录数据修改历史和操作日志
- 删除人物前展示受影响的关系和事件
- 阻止循环祖先、重复关系、自关联等非法数据
- 导入前展示新增、覆盖、忽略和冲突数量
- 为家谱提供手动快照，评估后续自动快照策略

验收标准：

- 用户可以自行恢复常见误删除和误修改
- 关键数据变更可以追溯到时间、操作者和变更内容
- 已知非法关系无法写入数据库
- 导入行为在执行前具有清晰、可确认的影响预览

### P0：工程质量清账

- 修复现有 ESLint 错误和警告
- 按 Next.js 16 当前规范迁移已弃用的 `middleware` 约定
- 补充人物、关系、导入和权限边界测试
- 增加搜索定位、删除确认、导入预检等关键交互测试
- 清理乱码、过期路线图描述和不统一术语
- 记录 AI 请求耗时、模型、失败类型和重试情况

验收标准：

- `npm test`、`npm run lint` 和 `npm run build` 全部通过
- 核心数据写入链路具有自动化测试保护
- AI 请求失败可以通过日志快速分类定位

### P1：GEDCOM 数据交换

第一阶段支持 GEDCOM 5.5.1 的核心子集：

- 导入人物、父母、配偶、子女和生卒信息
- 展示导入字段映射和冲突预览
- 输出无法识别字段的警告报告
- 支持核心数据导出为 GEDCOM
- 保留原始标识，便于后续增量导入研究

暂不追求完整覆盖所有冷门标签和厂商扩展字段。

## V1.3：资料中心与 AI 数字化

建议周期：4～6 周。

目标：让纸质族谱、照片、证件和口述整理材料真正进入家谱，并与人物、事件和关系建立可追溯关联。

### P0：文献与媒体基础模型

- 上传图片、PDF、扫描件和照片
- 创建文献或媒体资料条目
- 记录标题、来源、年代、提供者和说明
- 将资料绑定到人物、事件或整个家谱
- 在人物档案中展示相关资料
- 建立受权限控制的文件访问机制

### P0：AI OCR 审校工作流

```text
扫描件或照片
      ↓
OCR 原文与版面信息
      ↓
人物、事件、关系候选
      ↓
与现有家谱匹配
      ↓
人工审校草稿
      ↓
写入档案并保留原始资料引用
```

关键要求：

- OCR 结果不得绕过草稿确认直接写库
- 每条提取信息都能定位到原始资料或文本片段
- 用户可以修正 OCR 原文和结构化候选
- 对重名、年代冲突和关系方向不明继续使用多轮澄清

验收标准：

- 用户可完成“上传一页族谱—审校—写入人物和关系”的闭环
- 新增档案信息可以查看其资料来源
- OCR 或 AI 失败不会破坏原始资料和既有家谱数据

## V1.4：家族协作、审校与发布

建议周期：4～6 周。

目标：让多个家庭成员安全地贡献资料，由可信成员审校后形成稳定版本。

### 最小角色模型

| 角色 | 主要能力 |
| --- | --- |
| 所有者 | 管理家谱、成员、权限和全部数据 |
| 编辑者 | 新增和修改人物、关系与资料 |
| 审校者 | 审核其他成员提交的修改 |
| 访客 | 只读浏览被授权的内容 |

### P0：成员与权限

- 通过邀请链接或邮箱邀请家族成员
- 管理家谱成员和角色
- 所有数据访问从“创建者所有”演进到“家谱成员授权”
- 对文件、人物档案和管理操作实施服务端权限校验

### P1：贡献与审校

- 修改记录显示贡献者和修改理由
- 敏感修改或低权限成员提交进入待审队列
- 审校者可以接受、驳回或要求补充说明
- 支持围绕修改记录进行评论
- 区分工作草稿与已发布版本

验收标准：

- 家谱所有者可安全邀请至少一种非所有者角色
- 未授权用户无法读取或修改家谱数据和文件
- 一次成员贡献可以完整经过提交、审校和发布流程
- 已发布内容可追溯到贡献者、审校者和原始资料

## 暂缓方向

以下能力不进入 V1.2–V1.4 的核心范围：

- 社交动态流
- 实时多人光标或实时协同编辑
- 原生移动端应用
- 复杂商业订阅和计费系统
- 祠堂页面的大规模展示装修
- 无来源、全自动生成完整家族故事
- 为追求覆盖率而无限扩张亲属称谓规则

## 推荐执行顺序

1. 工程质量清账
2. 数据校验、软删除和操作历史
3. GEDCOM 导入预检与核心格式支持
4. 文献和文件基础模型
5. OCR 到可审校草稿
6. 家谱成员与角色权限
7. 协作审校与发布流程

## 版本出口

每个阶段达到下列结果后再进入下一阶段：

- V1.2：真实数据可安全维护、恢复和交换
- V1.3：真实资料可被上传、识别、引用和审校
- V1.4：多个家庭成员可在权限边界内共同维护并发布家谱

路线图描述产品方向和优先级。每个版本启动前，应再创建对应的 OpenSpec change，将范围拆成 proposal、design、specs 和 tasks，避免直接按路线图大包实现。
